# MAS Platform — Шпаргалка «как всё запускать»

Две среды, не путать:
- **КОМПЬЮТЕР (Windows)** — разработка и тесты. Здесь пишем код, гоняем на Ollama.
- **СЕРВЕР (облако, Ubuntu)** — боевая версия, работает 24/7 сама.

---

## ЧАСТЬ 1. КОМПЬЮТЕР (разработка)

### Каждый раз, когда сажусь работать
1. Открыть папку проекта в VS Code.
2. Проверить, что **Ollama запущена** (иконка ламы в трее). Без неё тексты будут-заглушки.
3. Открыть терминал в VS Code (**Ctrl + `**) и включить окружение:
   ```
   .venv\Scripts\activate
   ```
   В начале строки должно появиться `(.venv)`.
4. Запустить панель:
   ```
   python run_web.py
   ```
5. Открыть в браузере: **http://localhost:8000** → войти своим логином/паролем.
6. Остановить панель — **Ctrl + C** в терминале.

### Если хочу проверить расписание локально
Отдельный терминал (тоже с `(.venv)`):
```
python scheduler.py
```
(в `scheduler.py` вверху `TEST_MODE = True` — задачи запустятся через 1–3 минуты для проверки; для боевого режима на СЕРВЕРЕ там стоит `False`.)

### Первый запуск на новом компьютере (одноразово)
```
python -m venv .venv
.venv\Scripts\activate
pip install -r requirements.txt
python seed.py
python create_user.py
```
Плюс создать файл `.env` с секретами (см. Часть 4).

## ЧАСТЬ 2. СЕРВЕР (боевая версия)

### Как попасть на сервер (в командную строку)
Через **веб-консоль Aéza**: панель Aéza → ваш сервер → кнопка «Консоль». Логин `root` + пароль.
(Обычный SSH с вашего ПК не работает из-за блокировок — только веб-консоль.)

### Как открыть саму панель (в браузере)
По адресу Cloudflare-туннеля:
- временный: `https://…trycloudflare.com` (меняется при перезапуске туннеля)
- постоянный (когда настроим домен): `https://panel.ваш-домен`

### Управление службами (в консоли сервера, под root)
Проверить, что всё работает:
```
systemctl status mas-web mas-scheduler
```
Ищем зелёное `active (running)`. Выход из просмотра — клавиша `q`.

Перезапустить (после смены `.env` или обновления кода):
```
systemctl restart mas-web mas-scheduler
```

Посмотреть логи, если что-то не так:
```
journalctl -u mas-web -n 50 --no-pager
journalctl -u mas-scheduler -n 50 --no-pager
```

### Проверить, что WARP (обход блокировок) включён
```
warp-cli status
```
Должно быть `Connected`. Если нет:
```
warp-cli connect
```

## ЧАСТЬ 3. КАК ДОСТАВИТЬ ИЗМЕНЕНИЯ КОДА НА СЕРВЕР

Золотое правило: **код едет через GitHub**. Правим на компьютере → отправляем в GitHub → забираем на сервере.

### Шаг 1 — на КОМПЬЮТЕРЕ (после правок)
```
git add -A
git commit -m "что изменил"
git push
```

### Шаг 2 — на СЕРВЕРЕ (в веб-консоли)
Если репозиторий приватный — сначала на GitHub временно Make public, потом обратно Make private.
```
bash /home/mas/mas-platform/update.sh
```
Скрипт сам заберёт код, поставит новые библиотеки и перезапустит службы.

## ЧАСТЬ 4. СЕКРЕТЫ (.env)

Файл `.env` в Git НЕ попадает — он свой на компьютере и свой на сервере.
Строки внутри:
```
TELEGRAM_BOT_TOKEN=...      # токен бота от @BotFather
TELEGRAM_CHAT_ID=...        # ваш личный id (для отчётов в личку)
TELEGRAM_CHANNEL_ID=@...    # канал для публикации постов (бот должен быть админом!)
GIGACHAT_CREDENTIALS=...    # ключ GigaChat (только на сервере; дома работает Ollama)
```
Изменить `.env` на сервере:
```
nano /home/mas/mas-platform/.env
```
(Ctrl+O, Enter — сохранить; Ctrl+X — выйти) → потом `systemctl restart mas-web mas-scheduler`.

## ЧАСТЬ 5. ЕЖЕДНЕВНАЯ РАБОТА В ПАНЕЛИ (для оператора)

1. **Обзор** — сводка: клиенты, счётчики, последние запуски.
2. **Клиент** (ссылка «настройки и запуск») — профиль бренда, контент-план, конкуренты,
   кнопки запуска агентов.
3. **Запустить агента** — синяя кнопка. Результат появится в «Журнале запусков»
   через 1–3 минуты (страница обновляется сама).
4. **Контент на согласовании** — черновики. Зелёная кнопка публикует/утверждает,
   красная отклоняет. Пост в Telegram уходит только после вашего «✅».

## ЧАСТЬ 6. БЫСТРАЯ ДИАГНОСТИКА

| Симптом | Что проверить |
|---|---|
| Панель не открывается | WARP на ПК; открыть с телефона; жив ли туннель на сервере |
| Агенты пишут «[Черновик без LLM]» | На сервере: есть ли `GIGACHAT_CREDENTIALS` в `.env`; дома: запущена ли Ollama |
| Посты/отчёты не идут в Telegram | `warp-cli status` = Connected; бот — админ канала; `TELEGRAM_CHANNEL_ID` заполнен |
| Служба не `running` | `journalctl -u mas-web -n 50` — смотреть последнюю ошибку |
| После правки кода ничего не изменилось | Забыл `git push` (ПК) или `update.sh` (сервер), или рестарт служб |

## ГЛАВНОЕ ОДНОЙ СТРОКОЙ
- **Дома:** `.venv\Scripts\activate` → `python run_web.py` → localhost:8000
- **Сервер живёт сам.** Тронул код → `git push` дома → `update.sh` на сервере.
- **Секреты — в `.env`**, после правки — рестарт служб.
